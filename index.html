01 — Analytics & BI

Making five million daily card transactions reportable

A credit card portfolio ran on manual reporting, and nobody could show which numbers had been checked before they reached a deck.

AWS GluePySparkPythonRedshiftSQLPower BIIAM

Problem

High transaction volume, reporting built by hand each cycle, and no evidence trail behind the figures.

What I built

  • Automated ETL through Glue and PySpark into Redshift
  • Validation, reconciliation, metadata and lineage
  • IAM-based access control
  • Power BI views for utilization, spend, payments, delinquency

Result

Reporting moved from manual assembly to a pipeline with checks that run before anyone sees a number.

Limits

The 40% manual-reporting reduction, 30% faster runs and 99.5% pass rate are the design targets, not production measurements.

02 — Data engineering

A healthcare data platform that refuses bad rows

Claims, member, provider and pharmacy feeds change shape without warning. This platform catches that before an analyst or an AI agent ever sees the data.

PythondbtSnowflakepytestGitHub ActionsSQLRBAC

Problem

Healthcare feeds arrive dirty and drift over time, and a governed metric is worthless if the row beneath it is wrong.

What I built

  • Idempotent loads with source data contracts
  • Schema-drift flags and quarantined bad rows
  • A governed metrics layer with Snowflake RBAC and masking
  • An AI query agent with SQL guardrails and PHI redaction

Result

60+ dbt tests and 32 pytest tests run in CI on every change, so a breaking feed fails the build instead of the dashboard.

Limits

Built on synthetic data, so the privacy and masking layers are demonstrated rather than certified against a real payer feed.

03 — AI & GenAI

Policy answers that show their source

Card policy and fraud questions meant hunting through long PDFs, and a plain chatbot would answer confidently without showing where the answer came from.

PythonLangChainPineconeOpenAIRAGStreamlit

Problem

Answers had to be traceable to a clause in a policy document, not generated from an unverifiable model.

What I built

  • Ingestion with text extraction and overlapping chunks
  • Embeddings stored and retrieved in Pinecone
  • LangChain retrieval that keeps answers tied to the source
  • A Streamlit app for multi-PDF upload and plain questions

Result

An evaluation framework scores retrieval relevance, grounded accuracy and latency, so changes can be compared instead of guessed at.

Limits

It runs locally rather than as a hosted demo, and the evaluation set covers card policy documents only.
